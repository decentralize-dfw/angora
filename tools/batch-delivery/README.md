# Web delivery

Install with `pnpm install --frozen-lockfile`, then run `node build.mjs PATH_TO_NATIVE_GLTF_EXPORT_DIRECTORY`.
The input directory contains the authored `manifest.json`, six original glTF parts and their texture/buffer files. The source blend hash is recorded in the output report. Outputs go to `build/web/batched/{desktop,mobile}`.

Materials are sorted into finish families and compatible transparency/AO/indirect-light groups. Up to sixteen material tiles share a 512 px WebP atlas. Vertices retain repeating source UVs and a material index; the viewer wraps atlas lookups per fragment, with padded edges and bounded mip levels. AO and indirect-light UV channels remain separate. Existing vertex colors remain attached to the geometry. Glass uses an inexpensive alpha/environment response instead of a transmission scene pass.

The house, interior and garden are not decimated. Draco quantization is lossy: desktop house positions use 17 bits, mobile 16 bits. Only context geometry is simplified, with bounded relative error; desktop and mobile have separate settings recorded in `report.json`. This is a web quality/performance tradeoff, not a lossless texture claim. Original Blender files are not overwritten.

All six parts load before the first view, and remain resident. Switching floors performs no asset loading or decoder work. Decoder workers are released after loading. Baked AO/indirect illumination, HDR reflections and direct lights replace runtime GTAO, transmission and shadow scene passes for the batched delivery. Dimension geometry uses at most two additional draw calls; SVG witness endpoints identify the measured spans.

Run viewer tests with `node --test tests/*.test.mjs` from `viewer`. Tests enforce Draco, profile-bounded WebP images (1024px desktop / 512px mobile), scene package budgets of 24 MiB desktop / 17 MiB mobile including new lighting/reflections, at most 40 model primitives, retained AO, and no repeat loads across all views. `#viewport` exposes actual all-pass frame statistics and loading timings for manual browser checks. The complete renderer budget is 50 calls, including annotations and section meshes.

`context-additions.json` registers eight missing footprints from the September 15 OpenStreetMap snapshot against the existing CAD settlement. The registration RMS is about 2 m. Each addition copies all 46 authored B4 objects (45,806 triangles, including the foundation) from `build/web/full/context.glb`. Placement is rigid: no anisotropic scaling and no triangle selection from spatial bounds. Existing finish materials and donor AO/indirect UVs are reused. Basement elevations are sampled from the current ground mesh. Each garden has terrain-following limestone boundaries, a gate opening and an asphalt connection to the existing road surface. Ground additions stay in one batch and buildings in five. `build/web/batched/context-placement.json` records the computed elevations and road connections. These are approximate interpreted garden boundaries, not surveyed parcels. Building numbers 1/28 are inferred from sequence. The map does not verify facades or heights.

Use `ANGORA_REBUILD_PART=context-ground,context-buildings` to regenerate only those delivery parts. The subject villa, interior, garden and existing moving-section atlas remain byte-for-byte unchanged.

Moving wall sections use a gzip-compressed atlas sampled every 8 cm from the current architecture. Its nearest contour follows the exact animated clipping height, with at most 4 cm horizontal-section sampling offset; vertical walls retain their footprint. Only one transition geometry stays on the GPU. Four final floor contours remain unchanged. This avoids stencil scene passes and runtime triangle slicing.

Use `?profile=mobile` or `?profile=desktop` for reproducible profile testing. Automatic selection uses the primary pointer. Browser viewport emulation does not establish physical phone performance.

## Baked receiver lighting

`bake-ground-light.py` runs in background Blender against the delivered desktop GLBs. Run once normally for terrain and once with `-- --interior` for the four floor receivers. It traces the default solar direction and short ambient rays against opaque geometry; blended glazing is excluded. Both outputs are 512px packed visibility maps (R = sunlight, G = local ambient). The floor atlas has four 256px tiles. Run `node prepare-visibility.mjs` to convert the PNG intermediates to lossless WebP after a 0.55px reconstruction blur and update the manifests' content hashes. The two current maps total 21,748 bytes and are shared between profiles.

The runtime samples each map only in the existing receiver materials, with normal/height gating to avoid projecting ground shadows onto walls or furniture. Directional-sun visibility fades out when the user moves the sun away from the authored direction; local ambient visibility remains. Room spot lights and baked indirect daylight remain separate. These are static receiver shadows, not realtime ray tracing or moving-light shadows. Geometry and original PBR atlases are unchanged. Batched indoor plaster now receives a neutral diffuse environment without removing colored specular reflections; Three's existing normal/roughness response is preserved, and alpha glazing becomes more reflective at grazing angles. No postprocessing or additional scene render is introduced.

The context shaders skip interior spot/point-light loops. Plot-boundary calculations run only while white context mode is enabled; context building batches are already entirely outside the subject parcel and need no per-pixel polygon test. These optimizations compensate for the receiver-map lookup without changing model detail.

## Optical response and output

`node tools/batch-delivery/surface-response.mjs` reads scalar IOR/specular/clearcoat properties from the authored glTF exports and stores per-part material responses in each manifest. The regular delivery build does this too. The existing batch ID selects dielectric Fresnel reflectance and coat roughness per vertex. Only batches containing authored clearcoat enable Three's physical coat lobe; metals retain their base-color Fresnel response. No geometry, atlas, transmission pass or per-floor download is added. Source specular-color texture maps are not newly baked by this step.

The batched desktop route now uses one half-float scene target and one edge-aware antialias/output draw. AgX and sRGB are applied once, after transparent blending. This replaces the previously missing desktop antialiasing; hardware multisampling was tested and rejected for its frame-time cost. Coarse-pointer phones retain direct canvas rendering and existing hardware antialiasing, with no additional target. Desktop does allocate approximately 12 bytes per drawing-buffer pixel for color and depth; this is not zero memory cost. Indoor walking uses a separate exposure and neutral hemisphere fill, reusing an existing light; the fill is a presentation approximation, not a new global-illumination bake.

On the same desktop browser at 1422x1120 and the same attic camera, a 15-second sample measured baseline commit 12a7bd9 at 15.5 FPS / p95 103.1 ms and the new route at 15.6 FPS / p95 96.9 ms. These are local requestAnimationFrame samples, not GPU timings or physical-phone measurements. Mobile-profile loading at 393x852 was 2671 ms locally; basement transition was 953 ms, with 43 total draws on the desktop output route. Physical phones skip the extra output draw. The 136 tests passed. This is not evidence of V-Ray/Unreal visual equivalence, fully dynamic GI, local ray-traced reflections, or lossless 512px material detail.

## September model finishing and moving earth section

The source Blender file remains untouched. The delivered derivatives now remove coplanar overlapping skins, add six closed stair underside slabs, open the master balcony sheer panels, and use a continuous world-aligned parquet UV field. Transparent atlas composition preserves alpha. The archived dolphin asset is centered at approximately 3.5 by 2.3 metres on the pool floor. These are intentional geometry/material edits, not byte-identical copies of the baseline model.

Broken ceiling and attic plaster maps were replaced with neutral matte plaster, without their blotchy AO/indirect maps or coarse vertex fixture lighting. This is a cleanup, not a fresh photorealistic lighting bake. Existing room probes and other baked illumination are retained.

Local rebuild order: `prepare-finishing.mjs`, `repair-finishing.py`, `stage-finishing.mjs`, `build.mjs .runtime/finishing/source`, then `refresh-detail.mjs` with `ANGORA_DETAIL_SOURCE=.runtime/finishing/source`. Geometry Python tools require NumPy, Shapely and mapbox-earcut. Next run `finish-sections.py`, copy its sections output into native-current, run `finish-moving-sections.py`, then `finish-soil-motion.py`. Navigation uses the read-only Blender `finish-navigation.py` followed by `connect-finishing.mjs`. The soil generator uses baseline commit 27dcb56 so subsequent runs do not expand the input void cumulatively.

Earth contours are precomputed every 10 cm from native terrain and garden surfaces, drawn in one cached mesh at the animated plane height. Small isolated foundation pockets are earth, while the owner-marked thin-wall depot stays empty. Wall transition geometries are reused on return visits. Camera and section animation follow wall time so throttled browser frames cannot stretch a one-second transition into tens of seconds.

Local desktop-profile observation: 41–43 draws, 4.60 s initial ready time. Mobile assets at 390x844 in a desktop browser: 43 draws, 6.78 s initial ready time, 1.46 s ground-floor transition including a 1.006 s browser frame gap, maximum measured JS frame work 7.4 ms. These are neither network benchmarks nor physical-phone/GPU timings. Physical phone validation is outstanding; below-cut exterior stair faces remain visible where real geometry lies below the cutting plane.

## Fixture bounce, room captures and selective detail

The current finishing step supersedes the earlier blanket 512px desktop texture limit. After the delivery build, run the Blender scripts `bake-electric.py` and `bake-room-probes.py` with the authored `angora-high-quality-bake-review.blend`, then run `refresh-detail.mjs`. Neither Blender script saves the source scene. The finishing script copies compressed geometry streams exactly and replaces only image buffer views. It checks every Draco stream before writing the resulting GLB. Desktop architecture/interior color, AO and indirect maps use 1024px; normal and roughness atlases retain their existing resolution. Mobile material atlases remain 512px. Atlas derivatives use each sampler's actual dimensions as compile-time constants, with mip limits derived from its padding.

Fixture illumination is computed using Cycles, 128 samples and six diffuse bounces, on the existing ceiling, interior-wall and main-floor UVs. Direct fixture lighting and its occlusion are included; sunlight and albedo are excluded. The map is added independently of the daylight map, and switches with the interior-light control. It is already geometrically occluded and is not multiplied by AO a second time. This replaces the interim artificial indoor hemisphere lift. These receivers no longer evaluate runtime spot lights. Remaining detailed furniture receives vertex-level diffuse fixture lighting, while sun and captured reflections retain per-pixel shading. This removes the expensive per-pixel fixture BRDF loops; vertex diffuse light on large unbaked faces is an approximation. Bakes are 1024px desktop / 512px mobile and retain linear intensity separately from sRGB encoding.

Four 64-sample Cycles panoramas supply static room reflections for the main reflective batches. They are prefiltered once during loading and remain resident across all floor changes and walking. These are floor-level approximations; they do not reproduce a mirror's view-dependent parallax, room-by-room visibility or changed sun positions. Panoramas are 512x256 desktop / 256x128 mobile. No runtime reflection scene pass is added. The profile budgets, including these captures and lighting maps, are 24 MiB desktop and 17 MiB mobile. They exclude the existing application bundle and shared outdoor HDR. Higher desktop resolution increases texture memory; it is not free quality. Physical phone verification is still outstanding.
